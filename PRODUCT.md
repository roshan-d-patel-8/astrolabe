# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users and purpose

Astrolabe is its owner's integrated personal operating interface over an Obsidian vault. It connects whole-system orientation to specific measures and executable tasks without losing context.

## Capabilities and constraints

- Exactly five Focus Mundi altitudes: F1 Compass, F2 Cartography, F3 The Real, F4 Lens, F5 Momentum.
- Ten life and work domains span Hathi and Skoll. Domain selection carries into measures and tasks.
- TaskNotes remains canonical. Public Pages is an encrypted build-time snapshot; the loopback companion reads canonical files on focus and every 60 seconds, and supports explicit edits and task/project creation. Hathi/reminder tasks remain excluded. No public write API or cross-device editing is offered.
- Every dashboard has curated focus/domain relationships and an in-site isolated source capture, plus a canonical Obsidian link. Source scripts, media, and live Dataview/base queries are not executed. Recorded refresh metadata is not proof that underlying data is current.
- Planning readings have no observation dates in the source and are not live telemetry. Do not invent trends or normalized scores.
- Personal source and snapshot are encrypted before publication. No access key or plaintext personal dataset belongs in public source control.

## Brand commitments

The Astrolabe, Axis Mundi, F1–F5, and The Real remain. The owner's explicit reference is Edward Tufte: show relationships and evidence, with precise labeling. Both light and dark modes are required. Celestial shaders and Three.js bring delight without interfering with reading and action.

## Evidence on hand

The canonical vault HTML supplies domain descriptions, value dyads, recorded readings, and questions. The build supplies dashboard metadata, sanitized source captures, active TaskNotes records, and projects. Explicit realm metadata takes precedence over task-keyword suggestions. Project grouping uses only canonical parentProject values; unassigned means unassigned, not a fabricated project. Integration tests follow focus-to-instrument and task-to-canonical-note workflows.
